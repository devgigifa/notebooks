Tipos de Dados e Variáveis

O sistema de tipos do C# é estático e fortemente tipado. Cada variável tem tipo definido em compile-time, garantindo segurança e desempenho.

Tipos por Valor vs por Referência

Tipos por valor (int, double, bool, char, decimal, struct): vivem na stack. Cópia cria valor independente.

Tipos por referência (string, class, arrays): vivem no heap; variável guarda ponteiro. Cópia copia o ponteiro.

var é inferência de tipo em compile-time — o tipo é fixo, não é dinâmico. Nullable types (int?) permitem que tipos por valor aceitem null.

tipos, var, nullable e conversões

Strings em Profundidade

String, StringBuilder e Interpolação

String é imutável: cada concatenação cria novo objeto. Para loops, use StringBuilder. Interpolação ($"...") é compilada para string.Format. Verbatim (@"...") ignora escapes — ideal para paths. Raw string literals ("""...""") (C# 11) permitem qualquer caractere sem escape.

strings, StringBuilder e formatação

Classes, Objetos e Encapsulamento

Classes são moldes. Encapsulamento protege o estado interno expondo só o necessário via propriedades e métodos.

Propriedades, init e required

{ get; set; } gera campo privado automaticamente. init permite definir só na construção (imutável depois). required (C# 11) obriga o caller a inicializar. Construtores primários (C# 12) declaram parâmetros diretamente na assinatura da classe.

Coleções Genéricas

List, Dictionary, HashSet, Queue, Stack, SortedDictionary e coleções thread-safe para concorrência.

Complexidade das principais coleções

  • List<T>: acesso índice O(1), busca O(n), inserção fim O(1) amortizado, meio O(n)
  • Dictionary<K,V>: busca/inserção/remoção O(1) amortizado via hash
  • HashSet<T>: pertinência O(1) — como Dictionary sem valor
  • SortedDictionary<K,V>: busca O(log n) via árvore — itens em ordem
  • Queue/Stack: Enqueue/Push/Pop O(1)
List, Dictionary, HashSet, Queue e Stack

LINQ — Language Integrated Query

LINQ integra consultas à linguagem. Funciona sobre qualquer IEnumerable<T> e é traduzido para SQL quando usado com EF Core.

Execução Adiada vs Imediata

Adiada: Where, Select, OrderBy, GroupBy — criam pipelines mas não executam até enumerar. Imediata: ToList(), ToArray(), Count(), First(), Sum() — disparam execução. Cuidado: enumerar uma query adiada duas vezes executa duas vezes a fonte.

Programação Assíncrona — async / await

O modelo async/await libera a thread enquanto espera IO, sem callbacks. Task, ValueTask, WhenAll e CancellationToken.

Como async/await funciona

Quando o compilador vê await, ele suspende o método, registra uma continuação e devolve o controle ao chamador — a thread não fica bloqueada. Quando a operação IO conclui, o scheduler retoma da continuação. Isso permite que uma única thread atenda milhares de requisições IO-bound concorrentemente.

Regra de ouro: métodos async retornam Task ou Task<T>. Nunca async void (exceto event handlers). ValueTask evita alocação de Task quando o resultado já está disponível (cache hit).

ADO.NET — Acesso de Baixo Nível

ADO.NET é a camada mais próxima do banco. SqlConnection, SqlCommand, parâmetros e proteção contra SQL Injection.

ADO.NET vs ORM

ADO.NET: controle total do SQL, máxima performance, mais verboso. ORM (EF Core): produtividade, mapeamento automático, migrations. Use ADO.NET quando precisar de queries complexas, stored procedures ou máximo desempenho.

SEMPRE use parâmetros (@nome) em vez de concatenar strings — evita SQL Injection. SEMPRE feche conexões com using.

ADO.NET com SQLite
Para rodar: dotnet add package Microsoft.Data.Sqlite — descomente o bloco e remova o bloco de simulação. O padrão do código é idêntico para SQL Server (System.Data.SqlClient), apenas a string de conexão muda.
