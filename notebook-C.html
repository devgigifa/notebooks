Programação em C, do zero ao SQLite

Leia o código de cada célula e clique em Executar para ver a saída. Algumas seções têm demos ao vivo — mexa nelas também.

Como as células rodam: um navegador não compila C. Cada botão Executar roda uma versão em JavaScript do programa, escrita para imprimir exatamente o que o gcc imprime (conferimos as 16 saídas caractere a caractere). O código mostrado é o C original — para compilar de verdade no seu computador, use o comando que aparece no topo de cada saída. Por isso o código é somente leitura: editar o C aqui não mudaria o resultado.

07

Funções

  • Protótipo: declaração antecipada que informa ao compilador o tipo de retorno e os parâmetros
  • Passagem por valor: a função recebe uma cópia — alterar dentro não altera o original
  • Passagem por ponteiro: a função recebe o endereço — altera o original
  • Escopo local: variáveis declaradas dentro de uma função existem somente ali
  • Escopo global: variáveis declaradas fora de qualquer função são visíveis em todo o arquivo

Vetores e matrizes

  • Vetor (array 1D): posições contíguas de memória, indexadas a partir de 0
  • Matriz (array 2D): vetor de vetores — mat[linha][coluna]
  • Tamanho do array: sizeof(arr) / sizeof(arr[0])
Atenção: C não verifica limites — acessar v[n] em um array de n posições é comportamento indefinido.

09

Ponteiros

  • &x → endereço de memória de x
  • int *p = &x → p armazena o endereço de x
  • *p → acessa/modifica o valor no endereço (desreferência)
  • O nome de um array já é um ponteiro para o primeiro elemento: v == &v[0]
   x = 42          p
 ┌────────┐      ┌────────┐
 │   42   │◀──── │ 0x1004 │
 └────────┘      └────────┘
  endereço        p guarda
  0x1004          o endereço
Dica: os endereços impressos são simulados e mudam a cada execução — no C real também mudam, porque o sistema operacional escolhe onde a pilha fica.

Strings

Strings em C são char[] terminados com '\0'. A biblioteca string.h oferece:

FunçãoO que faz
strlen(s)Comprimento (sem '\0')
strcpy(dst, src)Copia src em dst
strncpy(dst, src, n)Copia no máximo n bytes (mais seguro)
strcat(dst, src)Concatena src ao final de dst
strcmp(a, b)Compara: 0 = iguais, <0 = a<b, >0 = a>b
strchr(s, c)Ponteiro para a primeira ocorrência de c em s
strstr(s, sub)Ponteiro para a primeira ocorrência de sub em s
Repare: strlen("Programação") dá 13, não 11 — o strlen conta bytes, e “ç” e “ã” ocupam 2 bytes cada em UTF-8.

Alocação dinâmica de memória

ÁreaCaracterística
Stack (pilha)Variáveis locais, tamanho fixo em compilação, liberada ao sair da função
Heapmalloc/calloc, tamanho definido em execução, deve ser liberada com free
  • malloc(n) → aloca n bytes, conteúdo indefinido
  • calloc(qtd, size) → aloca e zera a memória
  • realloc(p, novo_n) → redimensiona um bloco existente
  • free(p) → libera o bloco
Atenção: sempre verifique se malloc retornou NULL e sempre faça free. Use o Valgrind para detectar vazamentos.

14

Conexão com banco de dados (SQLite)

SQLite é um banco de dados embutido — armazena tudo em um único arquivo .db, sem necessidade de servidor. É ideal para aplicativos desktop, mobile e embarcados.

  • sqlite3_open(path, &db) — abre/cria o banco
  • sqlite3_exec(db, sql, callback, 0, &err) — executa SQL simples
  • sqlite3_prepare_v2 + sqlite3_bind_* — Prepared Statements (evitam SQL Injection)
  • sqlite3_step — executa e avança pelo resultado
  • sqlite3_column_* — lê valores da linha atual
  • sqlite3_finalize — libera o statement
  • sqlite3_close(db) — fecha o banco
Atenção: nunca concatene strings do usuário diretamente no SQL. Use Prepared Statements.
Dica: a biblioteca SQLite não roda aqui; a saída vem de um banco em memória simulado em JS (inserir, filtrar, ordenar, atualizar, apagar e agrupar). Para usar o SQLite de verdade, compile no seu computador com -lsqlite3.
